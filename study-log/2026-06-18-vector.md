# Study Session — Vector

- **Date:** 2026-06-18
- **Skill:** /teach
- **Source material:** `vector` (wiki concept page), MML Ch.2 §2 intro
- **Goal:** Master the first atomic concept — what a vector really is (the foundation of all ML math)

## What we covered
- A vector is defined by a **membership test**, not by appearance: you can **add** two and **scale** by a number, and still get the same kind of thing.
- Rejected the "arrow (direction + magnitude)" definition by example — [170, 70, 30] (a person) has no meaningful magnitude.
- Component-wise mechanics: addition slot-by-slot, scalar multiplication on every slot. `n` in → `n` out.
- **Closure**: add/scale can never push you out of the set. The load-bearing idea of the whole topic.
- Proved the **zero vector** is forced into every vector space: 0·a = 0, and closure traps the result.
- What is NOT a vector: positive-only prices (scale by −2 escapes), unit-length arrows (adding escapes), category labels like "cat" (operations undefined).
- **Vector space** = the whole set/club that passes the test together, with its two operations. Met a **subspace** live (the line y = x = all equal-slot vectors).
- Why ML cares: every data point is a vector in R^n (person → R^3, 28×28 image → R^784, word embedding → R^300). Add = averaging/accumulating gradients; scale = weighting / learning-rate steps.
- The real-code trap: NumPy/PyTorch broadcasting silently does illegal "vector addition" on mismatched shapes.

## Key takeaways (in the human's words)
- "A vector is a way to represent data… closure means when you add and scale another vector you have a thing of the same kind."
- "Cat + cat is not possible" — category labels fail because the operations aren't even defined.
- "When we work with humans, the result of every ML operation gives us a human, not something else." (closure as a correctness guarantee)
- "It is a tool that is reusable" — the payoff of the abstraction: build distance/average once, works on all kinds of data.

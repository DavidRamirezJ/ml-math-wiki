# Study Session — Matrix

- **Date:** 2026-06-22
- **Skill:** /teach
- **Source material:** `matrix` (wiki concept page), `linear-mapping`, MML Ch.2 §2.2
- **Goal:** Master the second atomic concept — a matrix as the machine that *acts on* data; the bridge from storing data (vectors) to transforming it.

## What we covered
- A matrix **transforms** a vector (changes it: rotate / stretch / swap / squash) — not just "transports" it. That verb distinction mattered.
- **The engine of A·x:** take each **column** of A, **scale** it by x's matching number, then **add** the scaled columns. Crucially — this is *only* the two vector moves from last session (scale + add). No new operation hides inside a matrix.
- **Shapes:** columns = how many numbers go IN (input dim), rows = how many come OUT (output dim). Notation is rows × columns ("R before C"). So an m×n matrix is a machine R^n → R^m.
- **Matrix × matrix = chaining machines.** Inner numbers must match; outer survive: [a×b]·[c×d] needs b=c, gives [a×d]. Felt the plug-and-socket reason.
- **Order matters:** AB ≠ BA. Discovered by hand — rotate-then-flip a phone ≠ flip-then-rotate. Matrices are *actions*, and actions don't commute.
- **Identity** = do-nothing machine (I·x = x). **Inverse** = undo machine (A⁻¹·A = I).
- **Invertibility = the collision test.** A matrix has an undo button iff no two different inputs land on the same output. Collision (e.g. squash machine [a,b]→[a,0]) destroys information → no inverse. Proven cold on three fresh machines (P: sum-collision → no; Q: swap → yes, undo = swap again; R: crush-2nd → no).
- **Dual role:** the same grid is both a transformation (apply: x→Ax) and a system of equations (solve: given b, find x = A⁻¹b).
- **The ML payoff:** a neural-net layer IS a weight matrix W. A deep net = W₃·W₂·W₁·x = exactly the chaining learned today. **Training = nudging the numbers inside every W** (gradient = the scale/step idea). Layer sizes must connect (inner must match).
